# Contributing

## Before submitting changes

1. Read [PLAN.md](PLAN.md) and [docs/COMPLIANCE.md](docs/COMPLIANCE.md).
2. Keep provider-specific code outside the shared domain contracts.
3. Add or update tests for behavior changes.
4. Document public API changes.
5. Never commit API keys, access tokens, signing keys or personal data.

## Pull request expectations

- Explain the motivation and scope.
- List platforms affected.
- Include test/build results.
- Note compatibility changes.
- Confirm that provider usage follows applicable terms and documented interfaces.
